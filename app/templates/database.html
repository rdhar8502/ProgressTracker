Database Mastery & SQL Cheatsheet Reference

SQL Join Types Visual Breakdown

INNER JOIN (A ∩ B)

Returns only rows where the join predicate matches in BOTH tables.

SELECT * FROM A JOIN B ON A.id = B.a_id;
LEFT OUTER JOIN (A + (A ∩ B))

Returns all rows from Left table (A), with NULLs for unmatched Right rows.

SELECT * FROM A LEFT JOIN B ON A.id = B.a_id;
ANTI-JOIN (A - B)

Finds rows in A that have NO corresponding match in B.

SELECT * FROM A LEFT JOIN B ON A.id = B.a_id WHERE B.id IS NULL;
FULL OUTER JOIN (A ∪ B)

Returns all rows from both tables, filling NULLs on sides where unmatched.

SELECT * FROM A FULL OUTER JOIN B ON A.id = B.a_id;

Physical Join Algorithm Selection

  • Nested Loop Join: Optimal when the outer relation is small and the inner relation has a B-Tree index on join keys. Time: O(N * log M).
  • Hash Join: Optimal for large, unsorted equijoins (A.id = B.a_id). Hashes smaller table in RAM (work_mem) and probes with larger table. Time: O(N + M).
  • Sort-Merge Join: Optimal when both relations are already sorted on join keys or for inequality/range joins. Time: O(N + M).

Window Function Anatomy

FUNCTION() OVER (
  PARTITION BY column_a, column_b    -- Divides rows into independent groups
  ORDER BY sort_column DESC          -- Specifies order within each group
  ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW  -- Frame specification
)

Key Functions Cheat Sheet

  • ROW_NUMBER(): Generates strictly unique sequential integers (1, 2, 3, 4). Ideal for pagination & deduplication.
  • RANK(): Generates rank with gaps on ties (1, 2, 2, 4).
  • DENSE_RANK(): Generates rank without gaps on ties (1, 2, 2, 3). Required for "Find Nth Highest" queries.
  • LAG(col, offset): Reads value from preceding row. Ideal for day-over-day delta comparisons.
  • LEAD(col, offset): Reads value from next row.
  • NTILE(n): Divides rows into N quantiles (e.g. 4 quartiles, 10 deciles).

Storage Paradigm Decision Matrix

Storage Type Example Engines Best Use Cases Trade-offs
Relational (RDBMS) PostgreSQL, MySQL ACID transactions, financial ledgers, complex joins, strict schema Horizontal sharding complexity, fixed schemas
Key-Value Store Redis, DynamoDB Low-latency cache, session store, rate limiters, leaderboards No complex joins, memory footprint cost (Redis)
Document Store MongoDB, Couchbase Catalogs, dynamic user profiles, semi-structured JSON Multi-document transactions have overhead; 16MB doc limit
Wide-Column / OLAP Cassandra, ClickHouse High write throughput, sensor telemetry, analytical aggregations No ad-hoc queries on non-partition keys; eventual consistency
Vector Store pgvector, Pinecone LLM RAG embeddings, semantic search, recommendation similarity High dimensionality index build time (HNSW/IVFFlat)

Indexing & Leftmost Prefix Rules

Composite Index on (A, B, C):
  • WHERE A = 1 AND B = 2 AND C = 3 -> Full Index Scan
  • WHERE A = 1 AND B = 2 -> Index Scan (Matches prefix A + B)
  • WHERE A = 1 -> Index Scan (Matches prefix A)
  • WHERE B = 2 AND C = 3 -> Cannot use index! Missing leading column A.

EXPLAIN ANALYZE Plan Scan Types

  • Seq Scan: Reads full table heap sequentially. Fast for small tables, slow for massive tables without selective predicates.
  • Index Scan: Traverses B-Tree index to find row pointers (TIDs), then fetches pages from heap table.
  • Index Only Scan: Entire query payload satisfied directly by index pages without touching heap! (Fastest).
  • Bitmap Heap Scan: Gathers matching TIDs into in-memory bitmap, then reads heap pages in sequential physical disk order.
